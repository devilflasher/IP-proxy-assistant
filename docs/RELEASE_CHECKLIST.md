# V4.0 Chrome Web Store 发布检查清单

## 已在代码中完成

- Manifest V3 Service Worker，所有事件监听器在模块顶层注册。
- HTTP、HTTPS、SOCKS4、SOCKS5 与 Chrome 官方 `proxy` API 枚举一致。
- SOCKS4/SOCKS5 认证在保存和启用前明确拒绝。
- 启用代理会等待 `settings.set`，再读取有效配置和 `levelOfControl` 复核。
- 关闭代理恢复 `system` 模式，不伪装为“直连”。
- 捕获代理错误、认证失败、其他扩展控制和策略不可控状态。
- 不包含远程脚本、远程字体、自动测试请求或动态执行的远程逻辑。
- 认证配置仅存本地；旧版 `storage.sync` 数据在升级时迁移后删除。
- 发布脚本使用运行时文件白名单，不包含网页快照、研究资料、测试和开发文档。

## 开发者后台必须人工更新

1. 上传 `dist/IP-proxy-assistant-v4.0.0.zip`，不要直接压缩整个仓库。
2. 单一用途写为：保存、切换和诊断用户提供的 Chrome 代理服务器。
3. 商店说明必须写清：
   - HTTP/HTTPS 支持用户名密码；
   - SOCKS4/SOCKS5 仅支持无认证；
   - “HTTPS 代理”字段表示到代理入口使用 TLS；
   - 机场叠加需要 TUN/VPN/全局接管，仅系统代理不能串联；
   - “已配置”不等于已验证连通。
4. 权限理由：
   - `proxy` 用于设置/恢复 Chrome 代理和接收错误；
   - `storage` 用于本地保存用户配置；
   - `webRequest`、`webRequestAuthProvider`、`<all_urls>` 只用于任意网页触发的代理认证挑战。
5. 隐私政策 URL 指向 V4.0 的 `PRIVACY.MD` 公网页面，并确保网页可公开访问。
6. 当前商店页只披露“位置”，但代码实际处理的是代理配置和认证信息。应在隐私问卷中按后台现有分类如实披露“身份验证信息”，并取消不准确的“位置”披露（若没有其他位置处理）。
7. 截图与文案中把“已连接/实时监控/稳定可靠”等无法由代码保证的说法改成“已配置/错误诊断”。
8. 保留现有扩展 ID `dnbhefappamfbnghpgcpnfniojddeffk`，以更新方式发布，不要创建新商品。
9. 开发者账号开启两步验证，完成商店要求的非交易者/交易者声明。
10. 发布前在至少两台设备上各验证一组 HTTP 认证代理、一组无认证 SOCKS5，以及机场系统代理和 TUN 两种模式。

## 兼容性测试矩阵

| 场景 | 预期结果 |
| --- | --- |
| HTTP 无认证 | Chrome 接受配置，网页请求走静态代理 |
| HTTP Basic 认证 | 自动响应代理认证；错误密码最多重试两次并显示错误 |
| HTTPS 入口代理 | TLS 连接到代理入口；证书或握手错误可被报告 |
| SOCKS4 无认证 | 仅 IPv4 目标兼容；DNS 在本机解析 |
| SOCKS5 无认证 | TCP URL 请求可用；DNS 在代理端解析 |
| SOCKS4/5 带账号密码 | 保存/启用前拒绝并解释 Chrome 限制 |
| 机场仅系统代理 | 明确提示无法原生双层串联 |
| 机场 TUN/VPN | 到静态代理入口的连接继续经过机场 |
| 静态代理来源 IP 白名单 | 当前机场出口 IP 在白名单时才应成功 |
| 其他代理扩展/企业策略控制 | 不误报成功，显示控制权冲突 |

## 已知平台边界

- Chrome `proxy` API 不提供 VMess、VLESS、Trojan、Shadowsocks、Hysteria 等协议内核，也不提供两级代理链配置。
- Chrome SOCKS5 不支持认证、不代理 UDP；SOCKS4 目标只支持 IPv4，且目标域名在本机解析。
- 扩展无法在不访问测试服务器的前提下证明公网出口 IP，因此 V4.0 不做自动外部连通性测试。
